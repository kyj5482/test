# 흩어진 대회 기록을 어떻게 하나의 데이터로 모을까?

`관심사: 데이터` · `퍼즐 3조각`

기록을 직접 남기기로 하고 처음 만든 프로토타입이 swim.capsule이다. 이름 그대로 '기록의 타임캡슐'이다.

## 🧩 조각 1 — 원본을 원형 그대로 보존한다

가장 먼저 세운 원칙은 "가공하기 전에 먼저 보존한다"였다. 대회 결과지, 관련 뉴스 기사, 경기 유튜브 링크, 공식 기록을 원래 형태 그대로 저장한다. 출처 사이트가 사라져도, 대회 조직이 결과 페이지를 내려도, 캡슐 안의 원본은 살아남는다. 데이터 플랫폼에서 배운 것이 있다면, 원천을 잃으면 그 위에 쌓은 모든 것이 무너진다는 사실이다. 그래서 swim.capsule은 정제된 값보다 원본 자체를 먼저 지킨다.

## 🧩 조각 2 — 연도별 캡슐과 이중 언어

수집한 기록은 연도 기반 캡슐에 담는다. 아이가 어느 해에 무엇을 뛰었는지가 시간축으로 정리되니, 흩어져 있던 조각들이 자연스럽게 한 줄기로 이어진다. 그리고 한국 대회 기록은 영어로도 함께 보관한다. 언젠가 해외 대학이나 코치가 아이의 기록을 참고할 때, 한국어 결과지만 있으면 그 기록은 없는 것과 같기 때문이다. 사이트 자체도 KO/EN 이중 언어이고 hreflang, sitemap, JSON-LD 같은 SEO를 갖춰, 검색으로도 기록에 닿을 수 있게 했다.

## 🧩 조각 3 — 자동 수집과 중복 제거

기록을 손으로 하나씩 모으는 건 오래 못 간다. 그래서 `capsule-scrape`라는 자동 수집 스킬을 붙였다. 뉴스, 대한수영연맹, 유튜브, USA Swimming 데이터허브를 날짜 범위로 훑어 관련 기록을 끌어오고, 같은 경기가 여러 출처에서 겹쳐 들어오면 중복을 제거한다. 사이트는 의존성 없는 Node 정적 사이트 생성기로 만들어 GitHub Pages에 자동 배포된다. 흩어진 원본들이 하나의 신뢰할 수 있는 데이터셋으로 모이기 시작한 지점이다.
