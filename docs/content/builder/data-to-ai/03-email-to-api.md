# 이메일로 주던 데이터를 24/7 API로 바꾸면 무슨 일이 생길까?

`관심사: 데이터` · `퍼즐 3조각`

"그 데이터 좀 뽑아서 보내주세요." 데이터 조직의 하루가 이 이메일들로 시작되고 끝나던 시절,
수동 제공을 24/7 API로 바꾸며 일어난 변화.

## 🧩 조각 1 — 수동 제공은 친절이 아니라 부채다

이메일로 데이터를 뽑아주는 일은 한 건 한 건은 친절이지만, 쌓이면 조직의 부채다.
같은 요청이 반복되고, 뽑는 사람마다 쿼리가 달라 숫자가 어긋나고, 담당자가 휴가면 업무가 멈춘다.
가장 큰 비용은 보이지 않는 것 — **데이터를 쓸까 말까 고민하다 포기하는 사람들**이다. 요청의 마찰이 수요 자체를 죽인다.

## 🧩 조각 2 — API화는 기술 프로젝트가 아니라 표준화 프로젝트다

엔드포인트를 만드는 건 쉽다. 어려운 것은 그 뒤의 질문들:
이 지표의 공식 정의는 무엇인가? 어느 테이블이 원천인가? 누가 접근할 수 있는가?
이메일 시대에는 뽑는 사람의 머릿속에 있던 암묵지가, API 시대에는 **문서화된 계약**이 되어야 한다.
API화의 진짜 산출물은 엔드포인트가 아니라 이 계약서들이다.

## 🧩 조각 3 — 24/7이 되는 순간 데이터가 제품이 된다

사람이 자는 동안에도 데이터가 제공되기 시작하면 질적 변화가 온다.
다른 시스템이 우리 데이터 위에 자동화를 쌓기 시작하고, 대시보드가 아니라 서비스가 소비자가 된다.
"데이터 제공 업무"가 "데이터 제품 운영"으로 바뀌는 이 전환이, 이후 데이터 앱마켓 구상의 출발점이 됐다.
