# 문서 없는 시스템은 어떻게 인수할까?

`관심사: 플랫폼` · `퍼즐 3조각`

2017년, 커넥티드카 플랫폼 일원화의 출발점은 화려한 설계가 아니었다.
한국·미국·중국에 각각 존재하는, 서버 문서가 거의 없는 세 개의 시스템을 파악하는 일이었다.

## 🧩 조각 1 — 문서가 아니라 트래픽을 읽는다

문서 없는 시스템의 진실은 코드도 아니고 담당자의 기억도 아니다. **실제로 흐르는 트래픽**이다.
API 게이트웨이와 로드밸런서의 로그부터 잡으면, 어떤 API가 살아있고 어떤 API가 좀비인지가 먼저 보인다.
"이 기능 쓰는 데 있어요?"라고 묻는 대신, 호출량 0인 엔드포인트 목록을 들고 가서 "이거 꺼도 되죠?"라고 묻는다.

## 🧩 조각 2 — 인수 문서는 내가 쓰는 것이다

전임자의 문서를 기다리는 것은 오지 않는 버스를 기다리는 것과 같다.
인수 과정에서 알게 된 모든 것을 그때그때 내 손으로 적었다 — 그 문서가 몇 달 뒤 플랫폼 일원화의 설계 입력이 됐다.
인수인계 문서의 최종 소유자는 떠나는 사람이 아니라 **남는 사람**이다.

## 🧩 조각 3 — 모르는 채로 운영을 시작한다

전체를 다 파악한 뒤에 손대겠다는 계획은 아름답지만, 파악이 끝나는 날은 오지 않는다.
장애 대응을 직접 해보는 것이 가장 빠른 학습이었다. 새벽에 울리는 알람이 시스템의 급소를 정확히 가르쳐준다.
**운영이 곧 리버스 엔지니어링**이다. 단, 알람마다 문서 한 줄을 남긴다는 규칙과 함께.
